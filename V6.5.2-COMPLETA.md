# Doce Casa Store — V6.5.2 Completa

Esta entrega usa como base o código enviado para o projeto Doce Casa Store e consolida uma rodada adicional de implementação para homologação.

## Escopo implementado nesta rodada

- Numeração pública de pedidos no formato `DC-000001`, `DC-000002`...; pedidos antigos `PED-*` continuam reconhecíveis.
- Pedido normal com vencimento de pagamento no mesmo dia.
- Mensagem de valor a pagar e aviso para desconsiderar caso o pagamento já tenha sido feito.
- Aprovação de pedido após pagamento, por administrador ou funcionário autorizado.
- Histórico/timeline operacional.
- Alterações estruturadas de pedidos normais.
- Preservação do preço congelado dos itens existentes; item novo usa o preço atual.
- Ajuste de estoque por diferença quando a alteração ocorre depois da reserva.
- Ajuste financeiro automático quando o total aumenta ou diminui.
- Registro de crédito, saldo adicional e refund-pending.
- Estorno explícito e idempotente.
- Tentativas de entrega e incidentes.
- Eventos operacionais idempotentes.
- Endereços múltiplos do cliente e seleção por `addressId`.
- Persistência de mensagens de atendimento.
- Lembretes de pagamento idempotentes, sem envio após pagamento.
- Dashboard com saldo a receber.
- Headers de segurança, CSP e `x-powered-by` desabilitado.
- Permissões de aprovação de pedidos.
- Teste estático V6.5.2.
- Compatibilidade com campanhas preservada.

## Regras importantes

Pedidos normais são independentes do calendário de campanhas. Campanhas mantêm suas próprias regras de pagamento e entrega.

O custo é sempre tratado internamente em centavos. Campos `*Cents` enviados pela API já são centavos; campos monetários comuns (`price`, `cost`, `amount`) são convertidos uma única vez.

## Homologação recomendada

1. Instalar dependências com `npm ci`.
2. Configurar `.env` a partir de `.env.example`, sem copiar segredos reais para o Git.
3. Rodar `npm run test:v65-complete`.
4. Rodar `npm run audit`.
5. Rodar os testes HTTP em banco isolado.
6. Testar WhatsApp/QR/reconexão.
7. Testar os fluxos de pedido, pagamento, alteração, separação, entrega e atendimento com dados de teste.
8. Só depois promover para produção.

## Segurança

Não incluir no ZIP: `.env`, banco de produção, `data/`, autenticação do WhatsApp, uploads reais ou tokens.

Não executar `npm audit fix --force` em produção. Dependências devem ser atualizadas e homologadas de forma controlada.

## Observação

Este pacote é uma **versão de implementação para homologação**, não uma declaração de que a infraestrutura de produção já foi validada. A homologação real do servidor e do WhatsApp continua necessária antes de substituir a versão em produção.
